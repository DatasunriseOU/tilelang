**Triton TTIR → TileLang TIR frontend code review (design/architecture focus)**

The scaffold follows the RFC (§5) extremely closely and is farther along than the "stubs-only" README claims — the 16-op emitters in `op_mapping.py` are **production-grade** (with real TIR emission, lazy TileLang imports, MLIR-vs-dict helpers, and target-aware fallbacks). The overall architecture is sound: TTIR hook (pre-layout), `WalkerCtx` as clean SSA → TIR bridge, `OP_TABLE` dispatch, and `pipeline.py` mirroring `tilelang/transform/__init__.py`. 

**Biggest strengths (design wins):**
- `WalkerCtx` (op_mapping.py:70-130) is an excellent abstraction — value_map + stmts + buffers decouples emitters from PrimFunc assembly.
- Lazy imports + `_operands`/`_results`/`_attrs` helpers (op_mapping.py:136-189) make the code testable without full MLIR bindings.
- RFC §5.2 stance in `layout.py:96-101` is correctly enforced (no TTGIR ingestion).
- Pipeline status/role tags (pipeline.py:42) make the "reuse/extend/skip" contract explicit and reviewable.

**Major design/architecture issues (the ones that matter):**

1. **PtrAnalysis is designed but not wired** — the single largest leaky abstraction.
   - Emitters everywhere assume `ctx.get(ptr_ssa)` returns `(buffer, indices)` tuple from `PtrAnalysis` (op_mapping.py:229, 269, 330, 715, 838, etc.).
   - `from_ttir` / `_walk_mlir_module` (poc/triton_frontend/__init__.py:275-279) never calls it.
   - Result: non-trivial pointer arithmetic falls back to the MVP `[0]` path (op_mapping.py:232-233), breaking everything beyond elementwise.
   - This is the **killer ambiguity** (see point 5).

2. **Text TTIR path is dead code for lowering** (`__init__.py:120-139`).
   - Only validates `OP_TABLE` coverage; never emits to `ctx`.
   - Real path is MLIR-only. Duplicated walker logic (text vs `_recurse`) is unnecessary once bindings are confirmed.

3. **Over-coupling between op_mapping emitters and ptr_analysis**.
   - Emitters reach into `ctx` and assume prior analysis (see RFC §5.1 "ptr_analysis has already populated").
   - No extension point for "alternative pointer lowering" (e.g. future CUTile path). Violates single-responsibility.

4. **Pipeline over-engineering for Tier-1**.
   - 28-entry `PASS_ORDER` (pipeline.py:86) includes many NV/Hopper-specific passes that are irrelevant for vector_add/softmax/matmul.
   - Status tags are mostly correct ("reuse" for TileLang passes, "extend" for Triton-specific like `FuseMBarrierArriveExpectTx`), but `ClusterPlanning` is marked skip yet has special-case enable logic (pipeline.py:238) — awkward.

5. **Minor naming/clarity issues**:
   - `map_tt_mbarrier` (op_mapping.py:730) and `map_tt_async_copy` (683) handle multiple TTIR spellings — good, but the docstring claims "async_copy / tt.async_commit / tt.async_wait" while table has separate entries (good duplication for clarity).
   - `TileLangPrimFunc = Any` (init.py:51) is fine for scaffold but leaks into public API.

No major duplicated logic or over-engineering elsewhere. The design is pragmatic and RFC-aligned.

### 1. Op-mapping holes (validation against `tilelang/language/__init__.py`)

All 16 ops in `OP_TABLE` (op_mapping.py:913-941) have **direct or near-direct TileLang support**:

- `tt.load` / `tt.store` → `T.copy` (language/__init__.py:58) or raw `BufferLoad`/`BufferStore` (emitters do the latter + mask — correct).
- `tt.atomic_rmw` → `atomic_add`/`atomic_max`/... (language/__init__.py:89-104, exact match in `map_tt_atomic_rmw`).
- `tt.dot` → `gemm` (language/__init__.py:60).
- `tt.reduce` → `reduce_sum`/`reduce_max`/`reduce_min` (language/__init__.py:69-86). **Hole**: `'mul'` combiner (op_mapping.py:539) — no `reduce_prod` visible. Propose: add `T.reduce_prod` or lower via `T.reduce(..., combiner="mul")`.
- `tt.where` → `tir.Select` (perfect, no TileLang primitive needed).
- Shape ops (`broadcast`/`splat`/`expand_dims`/`reshape`/`make_range`) → logical rebinds + `view`/`reshape` (language/__init__.py:96). Correct per RFC 5.1; physical work done by `LayoutInference`.
- `async_copy` / commit / wait → `T.async_copy` (language/__init__.py:58) + no-op for commit/wait (correct; handled by `InjectSoftwarePipeline`).
- `mbarrier` / barrier_* → `alloc_barrier` + `barrier_arrive`/`barrier_wait` (language/__init__.py:47) + `tvm_storage_sync` fallback. Good.
- `tt.experimental_descriptor_load/store` → `T.tma_copy` (language/__init__.py:58) or `T.copy` fallback. Target-aware (`_is_nv_target`).
- `tt.print` → `T.print` / `printf` (language/__init__.py:87).

**Only real hole**: `reduce` `'mul'` (already noted in code). All others map cleanly.

### 2. Pipeline order review

`PASS_ORDER` (pipeline.py:86) is an excellent match to the real `tilelang/transform/__init__.py` exports. Status tags are mostly accurate.

**Minimal Tier-1 subset** (vector_add, softmax, matmul — RFC 5.5):
- `LayoutInference`
- `LowerTileOp`
- `IfStmtBinding` + `MergeIfStmt` + `LoopUnswitching` + `VectorizeLoop` (load/store predicates)

### 3. PtrAnalysis driver

**Correct architectural choice**: C++ shim (`ptr_analysis.py:53` + `_load_shim`) is necessary. `mlir-python-bindings` alone are insufficient — `PtrAnalysis` is **not** an MLIR `Pass` (stateful `DenseMap<Value, PtrState>`, recursion into regions, `GetStructuredStateOp`, custom `tts` dialect). The vendored triton-shared approach (RFC §3) is the right one.

**Recommended flow** (to be added in `__init__.py`):
```python
# after obtaining ttir_module
if isinstance(ttir_module, str):
    ttir_module = ... # parse
pa = PtrAnalysis(ttir_module)
pa.rewrite()  # or extract_states()
# then pass states to WalkerCtx or run a separate lowering pass that populates ctx.value_map for pointer SSAs
```

**Improved `map_tt_load`** (op_mapping.py:196 — fixes fallback comment, adds explicit PtrAnalysis expectation, minor robustness):

```python
def map_tt_load(op: Any, ctx: WalkerCtx) -> Any:
    """Lower ``tt.load(ptr, mask, other)`` to a guarded ``BufferLoad``.

    PtrAnalysis (poc/triton_frontend/ptr_analysis.py) must have run and
    populated value_map[ptr_ssa] = (buffer, indices) tuple.
    """
    tir = ctx.tir()
    operands = _operands(op)
    if len(operands) < 1:
        raise ValueError("tt.load: missing pointer operand")
    ptr_ssa = operands[0]
    mask_ssa = operands[1] if len(operands) >= 2 else None
    other_ssa = operands[2] if len(operands) >= 3 else None

    resolved = ctx.get(ptr_ssa)
    if isinstance(resolved, tuple) and len(resolved) == 2:
        buf, indices = resolved
    else:
        # MVP fallback (elementwise kernels). Real path requires PtrAnalysis.
        buf, indices = resolved, [0]  # TODO: remove once PtrAnalysis is wired

    load_expr = tir.BufferLoad(buf, list(indices))

    if mask_ssa is not None:
        mask_expr = ctx.get(mask_ssa)
        if other_ssa is not None:
            other_expr = ctx.get(other_ssa)
        else:
            dtype = _dtype_of(_results(op)[0]) if _results(op) else "float32"
            other_expr = tir.const(0, dtype)
        load_expr = tir.if_then_else(mask_expr, load_expr, other_expr)

    if _results(op):
        ctx.bind(_results(op)[0], load_expr)
    return load_expr
```

**Improved `map_tt_dot`** (op_mapping.py:402 — cleaner accumulator handling, explicit TileLang primitive):

```python
def map_tt_dot(op: Any, ctx: WalkerCtx) -> Any:
    """Lower ``tt.dot(a, b, c)`` to ``T.gemm(A, B, C)`` (tilelang/language/__init__.py:60)."""
    operands = _operands(op)
    if len(operands) < 2:
        raise ValueError("tt.dot: expected at least 2 operands (A, B)")
    a_ssa, b_ssa = operands[0], operands[1]
    c_ssa = operands[2] if len(operands) >= 3 else None

    a = ctx.get(a_ssa)
    b = ctx.get(b_ssa)

    attrs = _attrs(op)
    transpose_A = bool(attrs.get("transpose_A", False) or attrs.get("trans_a", False))
    transpose_B = bool(attrs.get("transpose_B", False) or attrs.get("trans_b", False))

    import tilelang.language as T  # type: ignore

    if c_ssa is not None:
        try:
            c = ctx.get(c_ssa)
        except KeyError:
            c = None
    else:
        c = None

    if c is None:
        result = _results(op)[0] if _results(op) else None
        out_shape = list(_shape_of(result)) if result is not None else []
        out_dtype = _dtype_of(result) if result is not None else "float32"
        if out_dtype in {"float16", "f16", "bfloat16", "bf16"}:
            out_dtype = "float32"
        c = T.alloc_fragment(out_shape or [1, 1], out_dtype)  # safer default

    handle = T.gemm(a, b, c, transpose_A=transpose_A, transpose_B=transpose_B)
    ctx.emit(handle)
    if _results(op):
        ctx.bind(_results(op)[0], c)  # in-place accumulator
    return handle
```

### 5. Killer ambiguity

**The one design choice that kills the approach if wrong: PtrAnalysis integration timing and contract with the walker.**

Current design assumes "PtrAnalysis ran *before* the op walker" (op_mapping.py:225 comment, multiple places). But the driver never calls it (`__init__.py:275`). 

**Right answer**: Run `PtrAnalysis` **once** on the TTIR module (before or interleaved with the walker) and let it rewrite the module / populate `ctx` with structured pointer states. Then emitters consume `(buffer, indices)`. This is exactly what `microsoft/triton-shared` does and matches RFC §5.1. The C++ shim already exists for this purpose (`ptr_analysis.py:138`). Wire it in `from_ttir` and the whole thing works.

Fix that one gap and the POC becomes production-ready for Tier-1 kernels. Everything else is already excellent.
