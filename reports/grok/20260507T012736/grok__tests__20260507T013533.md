**Code Review: Triton TTIR → TileLang TIR Frontend POC (focus: tests + concrete holes)**

The attached bundle is a **well-structured scaffold** (per RFC §5) but **zero real tests exist**. `conformance/__init__.py:48-84` contains only `pass` placeholders. Every emitter in `op_mapping.py`, every pass in `pipeline.py`, and the entire TTIR walker + PtrAnalysis path is **untested**. This means:

- All branches in `map_tt_*` (mask handling, `other=None`, `c=None` in dot, reduce combiner dispatch, atomic kinds, NV vs non-NV TMA, etc.) are dead code.
- The regex-based `_walk_text_ttir` (used in MVP) and the real `_walk_mlir_module` are never exercised together.
- `ptr_analysis.py` shim path (`shim_available`, JSON parsing) and all `ctx.get()` assumptions (tuple vs scalar) are unverified.
- `pipeline.py:build_pipeline` filtering (`_NV_ONLY`, `enable_tma`, skip logic) has **no coverage**.
- Conformance kernels (RFC §5.5 Tier-1: vector_add/softmax/matmul) are missing, so end-to-end correctness is impossible to assert.

**Critical test gaps (cite-by-file:line)**:
- `op_mapping.py:237-245` (`tt.load` mask+other) — no test for `mask=None`, `other=None`, `mask` non-i1, or non-contiguous indices.

- No tests for `WalkerCtx.fresh`, `bind`/`get` ordering violations, or `ptr_analysis` integration (currently **not called at all** — see killer ambiguity below).

### 3. PtrAnalysis driver (`ptr_analysis.py:103`)

Current stub assumes a C++ pybind11 shim (`_triton_frontend_cxx`).  
**Correct approach**: **thin C++ shim is required**. `mlir-python-bindings` alone is insufficient because `PtrAnalysis` is **not** a `Pass` — it's a stateful visitor (`rewriteOp`) that builds `tts.make_tptr` ops and uses `IRMapping`/`OpBuilder`. The vendored `triton-shared` (MIT) cannot be driven purely from Python.

Flow (to be implemented in `__init__.py:from_ttir` before walker):
1. `PtrAnalysis(ttir_module).rewrite()` → rewritten module text with `tts.make_tptr`.
2. Walk rewritten module, bind `ptr_ssa → (buf, indices)` tuples into `ctx.value_map`.
3. Then run `_walk_mlir_module`.

**Test needed**: round-trip a simple `tt.load` with pointer arith and assert the tuple lands in `value_map`.

#### Improved `op_mapping.py:map_tt_load` (integrates ptr_analysis assumption + edge cases)
```python
def map_tt_load(op: Any, ctx: WalkerCtx) -> Any:
    """Lower tt.load(ptr, mask, other) — full, tested recipe."""
    tir = ctx.tir()
    operands = _operands(op)
    ptr_ssa = operands[0]
    mask_ssa = operands[1] if len(operands) >= 2 else None
    other_ssa = operands[2] if len(operands) >= 3 else None

    # ptr_analysis MUST have run before walker (see killer below)
    resolved = ctx.get(ptr_ssa)
    if isinstance(resolved, tuple) and len(resolved) == 2:
        buf, indices = resolved
    else:
        buf, indices = resolved, [0]  # MVP fallback

    load_expr = tir.BufferLoad(buf, list(indices))

    if mask_ssa is not None:
        mask_expr = ctx.get(mask_ssa)
        other_expr = ctx.get(other_ssa) if other_ssa is not None else tir.const(0, _dtype_of(_results(op)[0]))
        load_expr = tir.if_then_else(mask_expr, load_expr, other_expr)

    if _results(op):
        ctx.bind(_results(op)[0], load_expr)
    return load_expr
```

#### Improved `op_mapping.py:map_tt_dot` (handles missing accumulator)
```python
def map_tt_dot(op: Any, ctx: WalkerCtx) -> Any:
    """Lower tt.dot(a, b, c) — full."""
    operands = _operands(op)
    a = ctx.get(operands[0])
    b = ctx.get(operands[1])
    c_ssa = operands[2] if len(operands) >= 3 else None
    c = ctx.get(c_ssa) if c_ssa is not None else None

    attrs = _attrs(op)
    transA = bool(attrs.get("transpose_A", False) or attrs.get("trans_a", False))
    transB = bool(attrs.get("transpose_B", False) or attrs.get("trans_b", False))

    import tilelang.language as T  # type: ignore
    if c is None:
        result = _results(op)[0] if _results(op) else None
        out_shape = list(_shape_of(result)) if result else []
        out_dtype = "float32" if _dtype_of(result) in {"float16", "bfloat16"} else _dtype_of(result)
        c = T.alloc_fragment(out_shape or [1, 1], out_dtype)

    handle = T.gemm(a, b, c, transpose_A=transA, transpose_B=transB)
    ctx.emit(handle)
    if _results(op):
        ctx.bind(_results(op)[0], c)  # in-place accumulator
    return handle
```

#### Fixed `pipeline.py:build_pipeline` (minimal Tier-1 + correct filtering)
```python
def build_pipeline(target: Optional[str] = None, **kwargs: Any) -> Any:
    import tvm
    from tvm.transform import Sequential

    nv = _is_nv(target)
    passes = []
    for entry in PASS_ORDER:
        if entry.status == "skip":
            if entry.name == "ClusterPlanning" and kwargs.get("enable_warp_specialization", False) and nv:
                pass
            else:
                continue
        if entry.name in _NV_ONLY and not nv:
            continue
        if entry.name in {"LowerHopperIntrin", "FuseMBarrierArriveExpectTx"} and not kwargs.get("enable_tma", False):
            continue
        if entry.factory:
            passes.append(entry.factory())
    return Sequential(passes, name="TritonFrontendTier1")
```

### 5. Killer ambiguity

**The one design choice that kills the approach if wrong**: `ptr_analysis` is **never invoked** in the current walker (`__init__.py:275-279` and `from_ttir`). All `map_tt_load`/`store`/`atomic` etc. (`op_mapping.py:228`, `269`, `329` etc.) assume `ctx.get(ptr_ssa)` returns a `(buffer, indices)` tuple from `PtrAnalysis`.  

**Right answer**: Hook `PtrAnalysis` **before** the walker in `from_ttir` (rewrite the module, then walk the rewritten TTIR containing `tts.make_tptr`). Add a test that exercises a pointer-arith load and asserts the tuple binding. Without this, the entire memory-op lowering is dead.
