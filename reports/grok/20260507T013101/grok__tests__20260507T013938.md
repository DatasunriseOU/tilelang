**Test Review Summary (focus area)**

The test suite in `poc/torch_dynamo/examples/` (the only runnable tests in the bundle) is a solid smoke-test foundation but **critically under-covers** the new orchestrator introduced in this POC (`fx_to_tilelang.py:867-1450`). Coverage is heavily biased toward the single happy-path `fused_linear` pattern (`_emit_fused_linear_region:1239-1299`). Almost every other code path is either skipped, caught-and-skipped, or asserted only at the level of “did not crash”.

**Concrete findings (file:line)**

**1. Untested branches / dead paths (high severity)**

- `fx_to_tilelang.py:1032-1040` (`on_call_function` → `NotImplementedError` from emitter → `_fallback_extern_op`):  
  All chain tests that hit `test_tiny_linear_layernorm_gelu_chain:175` and `test_tiny_attention_prim_chain:221` **catch the exception and `pytest.skip`**. The fallback path that records `("aten_extern", ...)` in `op_trace` and later produces an extern launcher is never asserted.  
  → No test ever verifies that a single missing op does *not* crash the whole graph (the exact contract documented at lines 1007-1013).

- `fx_to_tilelang.py:1166-1192` (`_partition_fusable_subgraphs` + `_NON_FUSABLE_BOUNDARY_OPS`):  
  The only test that touches partitioning is `test_tiny_matmul_relu_uses_real_tir:112-119`, which only exercises the single-region `fused_linear` case. No test inserts an `aten_extern` (or `print`) boundary and asserts that two independent `prim_funcs` are produced and chained by `_build_chain_launcher`.

- `fx_to_tilelang.py:1315-1320` (`_emit_sequential_region`):  
  This entire function is a stub that always raises `NotImplementedError`. Every multi-op test hits it and skips. The comment at 1307-1319 promises a future sequential path; today it is dead code with zero coverage.

- `fx_to_tilelang.py:1415-1444` (`_build_chain_launcher` – all_extern / single / multi branches):  
  The `all_extern=True` shortcut (line 1419) and the `len==1` fast-path (1430) are exercised, but the true multi-region chain (1442) is never reached. The fallback `gm(*runtime_inputs)` at 1443 is therefore untested.

- `__init__.py:142-146` (legacy forward-only fallback when `aot_autograd` unavailable):  
  `test_tinymm_relu_backward_matches_eager` and the chain tests run under modern PyTorch (where `aot_autograd` exists), so the `except ImportError` path is never taken. `_validate_graph` (lines 74-108) is therefore completely untested in the normal code path.

**2. Brittle / locking-in-incorrect behaviour**

- `torch_compile_smoke.py:176` and `test_torch_compile_chain.py:175,221`:  
  ```python
  except NotImplementedError as exc:
      pytest.skip(...)
  ```
  This turns a regression (new op added that should now lower) into a silent skip. The comment at `test_tinymm_relu_backward_matches_eager:140-143` acknowledges this is “Acceptable Phase 2.3”, but it locks in the current incomplete state.

- `torch_compile_smoke.py:78,193,239,279` (and chain tests 179,224):  
  `torch.testing.assert_close(..., rtol=1e-2/2e-2, atol=1e-2/5e-2)` on `float16`.  
  This is too loose for the `fused_linear` kernel (which should be bit-identical or within 1 ulp). It masks potential correctness bugs in the epilogue (`_epi` lambdas at 1260-1277) or the gemm policy.

- `test_tiny_matmul_relu_uses_real_tir:118`:  
  ```python
  assert has_prim or "extern slot" in src or "tilelang.compile ok" in src
  ```
  This string match is fragile to log-message changes and accepts the fallback path as success, defeating the purpose of the test (which is meant to prove *real* TIR).

**4. Backward test quality (smoke:106-148)**

- Relies on the exact FX decomposition produced by current PyTorch (`threshold_backward`, `mm`, `t`, `sum.dim_IntList`).  
  The big comment block (lines 91-101) is already outdated for newer torch versions.  
  **Suggestion**: replace the brittle `except NotImplementedError` skip with a proper parametrized test that exercises each bwd emitter (`emit_mm_backward:691`, `emit_t:639`, `emit_softmax_backward:749`, etc.) using synthetic bwd graphs (or `torch.autograd.Function` that produces known bwd FX).

- No test for `is_backward=True` path in `wrap_as_custom_op` (`custom_op_wrapper.py:193,224` – the `_tilelang_is_backward` tag and relaxed `_check_no_grad`).

**5. General test hygiene**

- All tests share the same `pytestmark` skip (`torch` + `tilelang`). Good, but `test_tiny_matmul_relu_uses_real_tir` should also skip the TIR-print block when `_no_tilelang_jit()` (already partially done at line 129).
- No test exercises `get_attr` / `param_tensors` with more than one parameter or with buffers.
- No test for multi-output FX graphs (the `if n_outputs == 1` path in `_meta` and `_fake` at `custom_op_wrapper.py:115,213` is only lightly exercised).
- No negative tests for shape mismatch inside emitters (e.g. `emit_matmul:262-263`).

**Recommendation for immediate PR**

1. Make the `NotImplementedError` skips into `xfail` (with a clear ticket) so they become visible regressions when we fill the emitters.
2. Add the 4 concrete test cases above (they each cover 50-100 lines of currently dead code).
3. Tighten tolerances for the real fused kernels and add a `torch.allclose(..., rtol=1e-5)` assertion when `has_prim` is True.
4. Extract a helper `def _compile_and_check(model, x, rtol=1e-5)` used by all forward tests.

These changes would raise test coverage of the orchestrator from ~30% (mostly the fused-linear happy path) to ~70% and make the test suite a reliable gate for future emitter work.
