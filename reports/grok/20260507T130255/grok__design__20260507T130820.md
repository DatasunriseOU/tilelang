**WAVE-7 + WAVE-8 BUGFIX AUDIT + DESIGN REVIEW**

I audited the six attached files (fp8_amax.py, dsa_splitk_indexer_loss.py, custom_op_wrapper.py, fx_to_tilelang.py, lower_tma_to_ptr_arith.cc, reduce_op.py) with the exact WAVE-7/8 commits you flagged. I reference file:line numbers from the provided sources.

### 1. fp8_amax.py — _expose_to_globals closure fix (WAVE-7 #1)
**Status: Correct, no regression.**

- The hack (`fp8_amax.py:50-80`, used at `make_fp8_amax_kernel:200` and `make_fp8_quantize_kernel:280`) is exactly as described: it mutates the *factory* function’s `__globals__` (module globals) before the `@T.prim_func` decorator runs so `typing.get_type_hints` can see `N`, `BLOCK`, `DTYPE`, `FP8_MAX`.
- No other functions in this file suffer the same closure-vs-parser problem (only the two `make_*_kernel` factories rebind these names).
- lru_cache on `_amax_kernel_for` / `_quantize_kernel_for` (`:390` / `:430`) guarantees synchronous completion → no overwrite race. Safe for this file.

**Design issue (HIGH maintenance smell):**  
This is a brittle parser workaround that violates “don’t mutate global/module state”. It couples the DSL parser internals to our kernel factories. If TileLang ever changes how it inspects decorators (or runs the parser in a different context), every Path-C kernel breaks silently.  
**Actionable simplification:** Move to a shared `tilelang_utils.py` and expose a `make_prim_func` helper that accepts an explicit `globals_dict` (or uses `types.FunctionType` + source rewrite once the parser cache issue is fixed). Or push the parser fix upstream. The current `_expose_to_globals` is the smallest possible patch but should be marked `@deprecated` with a TODO.

### 2. dsa_splitk_indexer_loss.py — IfFrame rebinding + wave-8 tiled Q-cache (WAVE-7/8)
**Status: Fixes are correct; no new regressions found.**

- The `if X <= 0: X = …` patterns that previously leaked (Immutable variable used outside its defining region) are gone. The code now uses `T.if_then_else` for `denom1` (`stage2` kernel, comment referencing `cac10a0` / `bbe9334`) and similar single-assignment locals. Good.
- Wave-8 tiled Q-cache (`_metal_block_overrides:180-220`, `_can_use_q_cache_v5_tiled` referenced in `dsa_splitk_indexer_loss_tilelang:850-870`) correctly downsizes `BLOCK_SQ ∈ {64,32,16,8}` for Metal 32 KB threadgroup budget when `AH > 64`. The `AH * BLOCK_SQ * 4` calculation in the docstring is preserved.
- Last-block / alignment handling is guarded by the existing `if gi < N`, `if valid`, `sq_idx < ASq`, `sk_idx < Sk`, and causal `sq_idx >= sk_idx` predicates everywhere. `ceildiv` + `_pick_block_size` (which enforces `BLOCK % THREADS == 0`) still holds after tiling.
- No other Python-level variable rebindings inside `@T.prim_func` bodies that I could find in the visible code (the monolithic kernels are ~300+ lines each but all use the `T.if_then_else` pattern now).

**Design issues:**
- Monolithic kernels (`make_dsa_splitk_stage1_kernel` ~400 lines, `make_dsa_splitk_stage2_kernel` even larger). Hard to read, test, or extend (online-softmax recurrence, KL term, Q-hoist, index-mask paths all jammed together).
- **Duplication with fp8_amax.py:** `_tilelang_available`, `tilelang_supports`, `_resolve_target`, `_TORCH_DTYPE_TO_TL`, `_pick_block_size`, `_is_metal`, block-constant tables, lru_cache kernel factories — all duplicated (or nearly so). This is the classic “Path C boilerplate” problem across every fused kernel.
- **Suggestion (high ROI):** Extract a single `cppmega_mlx.nn._tilelang.kernel_factory` (or similar) that owns target resolution, block picking, Metal overrides, dtype mapping, and the lru_cache wrapper. Both files (and the older `fp8_vecmat_path_c.py`) become thin callers. This eliminates ~150 lines of copy-paste and makes future targets (e.g. new Metal SIMDgroup size) one-place changes.

### 3. custom_op_wrapper.py + fx_to_tilelang.py — torch_dynamo / custom_op surface (WAVE-7 #4)
**Status: Solid. No regressions.**

- `custom_op_wrapper.py:220-250` correctly switched `_impl` / `_fake` to `-> List[torch.Tensor]` (schema inference fix).
- Multi-output handling (`n_outputs`, `if n_outputs == 1` vs tuple) in `_fake` and `_region_output_specs` (`fx_to_tilelang.py:1300+`) works for the 9-tuple flash-attention case (wave-8 wiring of `aten._scaled_dot_product_flash_attention_for_cpu`).
- Contiguity/aliasing guard (`_ensure_contiguous_inputs:60-120`) with warn-once cache is excellent (prevents silent parent-tensor corruption).
- `_derive_region_io` + `_build_chain_launcher` (`fx_to_tilelang.py:1400+`) correctly threads tensors through an `env` dict for multi-region cases instead of falling back to `gm.forward`.

**Design smell:**  
`fx_to_tilelang.py` is a very heavy orchestrator (linearize → dispatch → partition → materialize → chain launcher). Emitters are spread across the file (`emit_matmul:380`, `_emit_*` family ~500-1200) and tightly coupled to the op_trace list that is later consumed by region materialization. Adding a new op requires touching ATEN_DISPATCH, an emitter, fusion_patterns, and the materializer — classic missing extension point.

**Actionable simplification:**  
Introduce a registry:
```python
@register_aten_emitter("matmul")
def emit_matmul(...): ...
```
This would make the huge file much easier to navigate and extend (exactly what the RFC §7 Phase 2.2 emitter table was trying to achieve).

### 4. reduce_op.py — reduce_prod C++ lowering (WAVE-7 xfail → WAVE-8)
**Status: Still broken (as expected).**

- The warning (`reduce_prod:120-140`) and `_REDUCE_PROD_WARNED` global are still present. The underlying C++ invariant violation (“Only the last index of a buffer access may be a vector type.” in vectorize_loop.cc / storage_rewrite.cc) was not fixed in the visible WAVE-8 changes.
- Python API is correct (mirrors `reduce_sum` / `reduce_max` exactly), but the `mul` AllReduce path is unusable.

**Design note:** The `reduce()` macro’s scope dispatch (shared/fragment) is clean. The `cumsum_fragment` macro is a nice pragmatic workaround for fragment buffers. Keep the log/exp synthesis default for prod until the C++ pass is fixed.

### 5. lower_tma_to_ptr_arith.cc — Allocate dispatcher (WAVE-7 #3)
**Status: Correct and necessary.**

- `VisitStmt:380+` calling `TryVisitAllocateMutator` (vendored) before `StmtExprMutator::VisitStmt` is the exact pattern used elsewhere in TileLang (lower_thread_allreduce, vectorize_loop, etc.). It prevents the apache `StmtFunctor` vtable rejection of `tilelang::tl_tir::AllocateNode`.
- TMA decode + pointer-arith fallback (`BuildPointerArithCopy`, `DecodeCUtensorMapDataType` covering fp8 code 0) looks solid. `kEmitOpaque` toggle and swizzle pragma preservation are thoughtful portability features.

**Minor design nit:** The vendored Allocate passthrough is a necessary evil, but it makes the whole TMA pass dependent on TileLang’s internal TIR node representation. Document the dependency clearly (already done in the comment).

### Cross-file Design & Architecture Issues (biggest wins)

1. **Duplicated TileLang boilerplate (HIGH)**  
   `fp8_amax.py:100-160`, `dsa_splitk_indexer_loss.py:250-300`, and pieces of `fx_to_tilelang.py` all reinvent target family mapping, block picking, Metal overrides, dtype tables, `_tilelang_available`, etc.  
   **Fix:** One shared `TileLangTarget` + `KernelFactory` abstraction (see point 2 above). This is the single largest source of technical debt in the Path-C suite.

2. **Monolithic prim_funcs**  
   DSA kernels are huge. fp8 kernels are small but still contain the same pattern. Future kernels (fp8 matmul, flash-attn, etc.) will explode.  
   **Suggestion:** Aggressive use of TileLang macros (`@macro`) for common sub-pieces (online-softmax recurrence, Q-hoist, KL term, elementwise chains). The `reduce_op.py` style is the right direction.

3. **Missing extension points in fx_to_tilelang.py**  
   The orchestrator + emitter design is powerful but closed. Registry pattern (as noted) would make it extensible without touching the core walker.

4. **Clarity / naming**  
   - Many “wave-N” comments everywhere (good for history, but the code now reads like a changelog). Consider a `docs/wave_history.md` and prune inline comments to current state.
   - `_expose_to_globals`, `kEmitOpaque`, `_REDUCE_PROD_WARNED` — these are honest but ugly. They should live in a “known-technical-debt” section or module.

5. **Perf / over-engineering**  
   lru_cache(maxsize=256/64) + power-of-two bucketing in fp8_amax is excellent. The tiled Q-cache in DSA is the right kind of shape-aware tuning. No obvious perf regressions from the wave fixes.

**No high-severity correctness regressions** from the WAVE-7/8 changes. The closure fix, IfFrame fixes, custom_op schema fix, and TMA dispatcher are all ship-ready. The remaining blockers are architectural (duplication, monolithic kernels, parser hack, missing registry).
