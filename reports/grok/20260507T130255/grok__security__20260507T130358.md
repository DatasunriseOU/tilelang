### 1. **High-severity security issue (still present after WAVE-7/8)**
**File**: `dsa_splitk_indexer_loss.py`  
**Location**: `dsa_splitk_indexer_loss_tilelang` (sparse_loss=True branch, roughly the block containing `index_mask = torch.full(...).scatter_(-1, topk_idx64, 0.0)` and the subsequent `_dsa_debug_enabled()` guards)

- **Concrete attacker scenario**: An adversarial model (or poisoned training data) supplies `topk_indices` containing values `>= Sk` (or negative). In production (`CPPMEGA_MLX_DSA_DEBUG` unset/false) the **debug-only** `.max().item()` / `.min().item()` / `.all()` checks are skipped. `scatter_(-1, topk_idx64, 0.0)` performs an unchecked out-of-bounds write into the `index_mask` tensor on the GPU. Because `index_mask` lives in the same allocation pool as other activation/gradient buffers, this silently corrupts adjacent GPU memory. Result: model weight/activation corruption, NaN poisoning that propagates into the KL-loss, or (in a training loop with TP) cross-process memory corruption.
- **Why WAVE-7/8 made it worse**: The comment explicitly acknowledges the PyTorch CUDA scatter_ upper-bound bug (“does NOT check the upper bound in release builds”) and the NaN-poison guard for fully-masked rows. Both were deliberately gated behind the debug env “for perf”. This turns a correctness foot-gun into a **production security foot-gun**.
- **Tainted-data flow**: `topk_indices` flows directly from the model forward pass (or attacker-controlled input) → `topk_idx64 = ...to(int64)` → `scatter_` with zero validation.

**Fix (minimal, zero-perf cost in hot path)**:  
```python
topk_idx64 = topk_idx64.clamp_(0, Sk-1)  # or .clamp_(min=0).clamp_(max=Sk-1)
```
or keep the `.max()`/`.min()` but **remove the debug gate** (or make the env control only the *NaN-poison patch*, not the bounds check). The current design is the exact opposite of defense-in-depth for a GPU kernel.

(The same file’s `_dsa_debug_enabled()` path is the only place that ever calls `.item()`/`.all()` on GPU tensors in the hot path — another source of hidden syncs, but that’s perf, not security.)
