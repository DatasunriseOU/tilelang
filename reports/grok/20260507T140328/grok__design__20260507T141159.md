### Design & Architecture Findings (focus only)

**1. Duplicated kernel-factory boilerplate (highest-leverage simplification opportunity)**  
`fp8_amax.py:300-420` (`_amax_kernel_for` + `make_fp8_amax_kernel`) and  
`dsa_splitk_indexer_loss.py:780-850` (`_stage1_kernel_for` / `_stage2_kernel_for` + `make_dsa_splitk_*_kernel`)  
are 90 % identical (lru_cache + `_FP8_AMAX_LOCK` (or equivalent) + `_pick_block_size` + `dispatch_lower`).  
Same pattern exists in the (truncated) fx_to_tilelang region emission.  

**Violation**: leaky module boundaries + copy-paste surface for future bugs (target family, block snapping, Metal overrides).  
**Actionable**: extract `cppmega_mlx.nn._tilelang._kernel_factory` (one `_kernel_for` decorator + shared `_pick_block_size` + `_block_constants_for_target`). Both files become <50 LOC wrappers. Simplifies future Path-C kernels dramatically.

**2. `_expose_to_globals` hack still lives (necessary but architectural debt)**  
`fp8_amax.py:80-130` (and identical pattern in dsa). Mutates module `__globals__` so `@T.prim_func` parser can see `N`, `BLOCK`, `DTYPE`, `FP8_MAX`.  

This is the canonical “TileLang parser doesn’t respect closure/localns” workaround. The lock (wave-9) makes it safe, but it is a **violated abstraction** — we are fighting the decorator instead of the framework.  
**Suggestion**: keep it (it works), but isolate into `tilelang_utils.expose_closure_for_prim_func(fn, extra_globals)` and add a loud module-level comment linking to the upstream TileLang issue. Do **not** spread the pattern further.

**3. FXToTileLang god-class (fx_to_tilelang.py)**  
The orchestrator (lines ~400-1700+ in the truncated file) owns: FX walking, ATEN_DISPATCH, fusion pattern matching, region partitioning, intermediate allocation heuristics, multi-region I/O derivation, launcher chaining, and extern fallback.  

Classic single-responsibility violation. The `_derive_region_io`, `_build_chain_launcher`, `_partition_fusable_subgraphs`, and `_emit_*` families are tightly coupled through `LoweringContext.op_trace/value_map`.  
**Concrete smell**: `fx_to_tilelang.py:1715` (grid calculation site mentioned by meta) is buried inside this class; int32 wraparound risk is real on huge shapes.  

**Simplification**: split into  
- `FXGraphWalker` (trace + specs)  
- `RegionPartitioner`  
- `KernelEmitter` (per-region TIR)  
- `LauncherBuilder` (custom_op + chain)  

This would also create the missing extension point for new fusion patterns (currently hard-coded in `_fusion_patterns`).

**4. Global mutable state in two places (minor but leaky)**  
- `custom_op_wrapper.py:25` `_REGISTRY` + `_CONTIGUITY_WARN_SEEN` (frozen-set + lock)  
- `dsa_splitk_indexer_loss.py:70` `_SCATTER_SCRATCH_CACHE` + lock  

Both are reasonable per-process caches, but they make the modules non-reentrant and test-hostile. The contiguous warning set is especially “clever” (warn-once per op/slot/reason).  
**Better**: move both into a small `TileLangRuntimeState` singleton (or just accept the globals — they are not performance-critical).

**5. Target-specific block constants scattered**  
`fp8_amax.py:220` (`_BLOCK_SIZE_TABLE`),  
`dsa_splitk_indexer_loss.py:280` (`_metal_block_overrides` + `_DSA_STAGE*` constants).  

Duplicated “per-target defaults + Metal downsize logic”. The AH>64 heuristic in DSA is excellent perf work but lives in the wrong place.  
**Action**: shared `_tilelang_block_config.py` with a registry that `_metal_block_overrides` can query.

- `reduce_op.py:189-199` warp reduction lane-mask comment (meta item) — the intrinsics are now correct post-9a7d1d3e; the comment can be deleted.  
- Wave-*/grok-review comments throughout (e.g. `dsa_splitk_indexer_loss.py:50`, `fp8_amax.py:280`) — move to git history / docs/research. They clutter the source.
