**2. Remaining HIGH-severity issues: none.**

**Design & architecture assessment (focus areas requested)**

- **Abstractions hold cleanly.** `Frag` (extern.py:80-140) is the single source of truth for the tile contract. Everything downstream (validation, meta serialization, TIR emission, C++ passes) consumes it. No violated contracts.
- **No leaky modules.** Registry (extern_registry.py) is completely decoupled from the decorator surface; Python DSL only imports it as `_registry`. C++ side only sees the emitted `call_extern` prefix + block annotation (no Python leakage). `extern_intrinsic_meta.h` is a minimal shared header with zero TVM/DL dependency beyond FFI.
- **No duplicated logic.** Argument partitioning, body scrubbing, meta building, and validation are each in one place. The `register_or_replace` path is the only duplicate (deliberate, for REPL UX) and is atomic under the lock.
- **Coupling is appropriate and minimal.** Python → C++ is strictly via documented constants (`EXTERN_CALL_PREFIX`/`kExternCallPrefix`, `EXTERN_BLOCK_ATTR`/`kExternBlockAttr`) and the stable `build_meta` dict shape. No awkward string interpolation or hidden globals.
- **Extension points are present and obvious.** New targets via `valid_targets()` (extern_registry.py:140), new layouts/scopes by extending the Literal + frozenset (extern.py:50-60 + Frag `__post_init__`), new factories for other hardware fragments (pattern established by simdgroup_*). Adding a new target only requires a body map entry + one-line regex tweak in `_validate_body` if non-standard.
- **Naming/clarity excellent.** `Frag`, `extern_intrinsic`, `build_meta`, `simdgroup_a/b/c` factories, `kExtern*` constants — all self-documenting and match the RFC §6 terminology. Docstrings (especially the big one at the top of extern.py and the fusion-safety invariants) are precise and actionable.
- **No over-/under-engineering.** The scrubber (raw-string + comment + string stripping) is the only "clever" piece and is justified (and tested) to prevent false-negative warnings. The shape/buffer split is the minimal complexity needed to support natural call syntax `intrin(M, N, A, B, C)` while keeping the signature factory clean. Everything else is deliberately simple (dataclass + closure + lazy TVM import).
