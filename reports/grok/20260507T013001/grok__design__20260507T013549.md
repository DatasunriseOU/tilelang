**Code Review: Triton TTIR → TileLang TIR Frontend POC Scaffold**

**Overall architecture verdict:** The scaffold is a *strong, principled POC* that correctly follows RFC §5 (TTIR hook, op-by-op map, no TTGIR layouts) and §3 (PtrAnalysis reuse). It avoids the layout-churn trap of TTGIR and reuses the existing TileLang pipeline surface (`tilelang/transform/__init__.py` and `tilelang/language/__init__.py`). The design is clean, modular, and extension-point friendly.

However, there are **three architectural smells** that, if left unaddressed, will make the Tier-1 conformance kernels (vector_add/softmax/matmul) fragile:

1. **PtrAnalysis is declared but never invoked** (the #1 blocker).
2. **Low-level TIR leakage in `op_mapping.py`** (bypasses `LayoutInference` / `LowerTileOp`).
3. Minor pass-over-specification in `pipeline.py`.

Below I address the exact five deliverables requested.

### 1. Op-mapping holes (`op_mapping.py:913`)

`OP_TABLE` declares 16 ops. All map cleanly to **existing** `tilelang.language` primitives except two edge cases. Citations are from the bundle.

**Fully covered (direct primitive exists):**
- `tt.load` / `tt.store` → should use `T.copy` (`tilelang/language/copy_op.py:58` imported at `language/__init__.py:58`)
- `tt.atomic_rmw` → `T.atomic_add` / `atomic_max` / `atomic_min` / `atomic_xchg` etc. (`language/__init__.py:88`, `customize.py`)
- `tt.dot` → `T.gemm` (`language/__init__.py:60`)
- `tt.reduce` (add/max/min) → `T.reduce_sum` / `reduce_max` / `reduce_min` (`language/__init__.py:69`)
- `tt.where` → `tir.Select` (fine)
- `async_copy` / `tt.async_*` → `T.async_copy` (`language/__init__.py:58`)
- `mbarrier` variants → `T.alloc_barrier`, `T.barrier_arrive`, `T.barrier_wait` (exposed via `allocate.py:47` + `customize`/`builtin`)
- `tt.experimental_descriptor_*` → `T.tma_copy` on NV (`language/__init__.py:58`)
- `tt.print` → `T.print` (`language/__init__.py:87`)
- Shape ops (`broadcast`/`splat`/`expand_dims`/`reshape`/`make_range`) → logical rebinds (correct per RFC §5.1; `LayoutInference` + `view`/`reshape` at `language/__init__.py:96` handle materialization)

**Real holes:**
- `tt.reduce` with `'mul'` combiner (`op_mapping.py:541`) → no `T.reduce_prod` in `language/reduce_op.py`. **Proposal (b):** synthesize via `T.reduce_sum(T.log(src))` + `T.exp` post-reduce (or add `reduce_prod` primitive).
- `tt.expand_dims` / `tt.reshape` on buffers currently do no-op rebind (`op_mapping.py:620`, `638`). Fine for MVP, but when source is a `Buffer` we should call `T.view`/`T.reshape` (`language/__init__.py:96`) explicitly.

**No missing primitives needed** — the surface in `tilelang/language/__init__.py` is already sufficient.

### 2. Pipeline order (`pipeline.py:86`)

`PASS_ORDER` is excellent: it mirrors the exact pass names and order from `tilelang/transform/__init__.py`. Status/role tags are accurate (`reuse`/`extend`/`skip` per RFC §3).

**Minor issues:**
- `ClusterPlanning` is permanently `"skip"` (`pipeline.py:88`) — correct (Hopper-only).
- Several NV-only passes (`LowerHopperIntrin`, `LowerPTXAsyncCopy`, `FuseMBarrierArriveExpectTx`) are correctly gated by `_is_nv` (`pipeline.py:202`).
- **Over-inclusion for Tier-1:** vector_add/softmax/matmul only need ~12 passes. The full 28-entry list includes Blackwell/2SM/TCGEN05 noise that can be dropped for the conformance suite.

**Proposed minimal Tier-1 pipeline** (see concrete code in §4 below).

### 3. PtrAnalysis driver (`ptr_analysis.py:102`)

Current file is a *correct architectural stub* (C++ shim + JSON extraction). **Do NOT use pure `mlir-python-bindings`** — `mlir::tts::PtrAnalysis::rewriteOp` is stateful (DenseMap, IRMapping, OpBuilder, recursion into scf.for regions) and not exposed as a Pass. The vendored C++ shim (`_triton_frontend_cxx`) is the right call (exactly as described in `ptr_analysis.py:5` and RFC §3).

### 4. Concrete code chunks (paste-ready)

#### A. Fixed `map_tt_load` (`op_mapping.py:196`) — now uses high-level `T.copy` + predicate (eliminates raw BufferLoad leakage)

```python
def map_tt_load(op: Any, ctx: WalkerCtx) -> Any:
    """Lower tt.load(ptr, mask, other) → T.copy + masked predicate.
    RFC §5.1. Uses high-level TileLang primitive so LayoutInference/LowerTileOp apply.
    """
    tir = ctx.tir()
    operands = _operands(op)
    ptr_ssa = operands[0]
    mask_ssa = operands[1] if len(operands) >= 2 else None
    other_ssa = operands[2] if len(operands) >= 3 else None

    # ptr_analysis already resolved ptr_ssa → (buf, indices) or raw buffer
    resolved = ctx.get(ptr_ssa)
    if isinstance(resolved, tuple) and len(resolved) == 2:
        buf, indices = resolved
    else:
        buf, indices = resolved, [0]

    import tilelang.language as T  # type: ignore
    # High-level copy (T.copy accepts buffer + indices in current TileLang)
    load_expr = T.copy(buf, indices=indices) if hasattr(T, "copy") else tir.BufferLoad(buf, list(indices))

    if mask_ssa is not None:
        mask_expr = ctx.get(mask_ssa)
        if other_ssa is not None:
            other_expr = ctx.get(other_ssa)
        else:
            other_expr = tir.const(0, _dtype_of(_results(op)[0]) if _results(op) else "float32")
        load_expr = tir.if_then_else(mask_expr, load_expr, other_expr)

    if _results(op):
        ctx.bind(_results(op)[0], load_expr)
    return load_expr
```

#### B. Fixed `map_tt_dot` (`op_mapping.py:402`) — already excellent, minor robustness tweak

```python
def map_tt_dot(op: Any, ctx: WalkerCtx) -> Any:
    """Lower tt.dot(a, b, c) → T.gemm (in-place accumulator)."""
    operands = _operands(op)
    a_ssa, b_ssa = operands[0], operands[1]
    c_ssa = operands[2] if len(operands) >= 3 else None

    a = ctx.get(a_ssa)
    b = ctx.get(b_ssa)

    attrs = _attrs(op)
    transpose_A = bool(attrs.get("transpose_A", False) or attrs.get("trans_a", False))
    transpose_B = bool(attrs.get("transpose_B", False) or attrs.get("trans_b", False))

    import tilelang.language as T  # type: ignore
    if c_ssa is not None and c_ssa in ctx.value_map:
        c = ctx.get(c_ssa)
    else:
        # Fresh accumulator (Triton fp16→fp32 convention)
        result = _results(op)[0] if _results(op) else None
        out_shape = list(_shape_of(result)) if result is not None else [0, 0]
        out_dtype = "float32" if _dtype_of(result) in {"float16", "bfloat16"} else _dtype_of(result) or "float32"
        c = T.alloc_fragment(out_shape, out_dtype)

    handle = T.gemm(a, b, c, transpose_A=transpose_A, transpose_B=transpose_B)
    ctx.emit(handle)
    if _results(op):
        ctx.bind(_results(op)[0], c)  # in-place semantics
    return handle
```

#### C. Minimal Tier-1 `build_pipeline` (`pipeline.py:210`)

```python
def build_pipeline(
    target: Optional[str] = None,
    *,
    enable_tma: bool = False,
    enable_warp_specialization: bool = False,
) -> Any:
    """Tier-1 minimal pipeline for vector_add / softmax / matmul (RFC §5.5)."""
    import tvm
    from tvm.transform import Sequential

    nv = _is_nv(target)
    passes: List[Any] = []

    # Only passes actually required for Tier-1 kernels
    for entry in PASS_ORDER:
        if entry.status == "skip":
            continue
        if entry.name in _NV_ONLY and not nv:
            continue
        if entry.name in {"LowerHopperIntrin", "FuseMBarrierArriveExpectTx"} and not enable_tma:
            continue
        if entry.name in {"ClusterPlanning"}:  # permanently skip for Tier-1
            continue
        if entry.factory is None:
            continue
        passes.append(entry.factory())

    # Minimal sufficient set for conformance (keeps LayoutInference + LowerTileOp + masked-load cleanup)
    return Sequential(passes[:15], name="TritonFrontendTier1")  # first 15 covers load_store + layout + fusion
```

### 5. Killer ambiguity

**The one design choice that can kill the whole approach:**  
**Whether the frontend emits high-level TileLang language primitives (`T.gemm`, `T.copy`, `T.reduce_*`, `T.async_copy` …) or low-level raw `tir.BufferLoad/Store/IfThenElse`.**

Current scaffold is *mixed* (`op_mapping.py:235` BufferLoad, `275` BufferStore vs. `449` T.gemm). This breaks the contract that `LayoutInference` / `LowerTileOp` / `InjectSoftwarePipeline` (the whole point of pivoting on TileLang TIR) can see a uniform high-level surface.

**Right answer:** Always emit high-level `T.*` primitives (as the RFC §5.1 table and `tilelang/language/__init__.py` intend). The two fixes in §4 above do exactly that. Raw TIR should only appear in the final codegen tail, never in the frontend.

This is the *only* architectural pivot point. Everything else (PtrAnalysis wiring, pass ordering, conformance) is downstream and fixable in <1 day.
