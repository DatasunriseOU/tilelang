**2. Remaining HIGH-severity issues (blockers — must be fixed before ship)**

These are **new or unaddressed regressions** relative to the wave-1/2 intent. All are in the *primary* aot_autograd path (the fallback path still works).

**HIGH 1: AOT path is completely broken at import/runtime (import error)**  
`aot_autograd_glue.py:226` (inside `_compile_one_side`):  
```python
from . import _validate_graph  # noqa: WPS433
_validate_graph(gm)
```  
`_validate_graph` is **defined locally inside `__init__.py:40-75`** (not exported, not a submodule, not in `fx_to_tilelang`).  
Result: `ModuleNotFoundError` (or AttributeError on the name) the moment `tilelang_fw_compiler` or `tilelang_bw_compiler` runs. The main aot_autograd path is dead.  
(This is the exact kind of cross-module private import that wave-1/2 tried to eliminate.)

**HIGH 2: Infinite recursion on any SymInt/dynamic-shape graph**  
`aot_autograd_glue.py:312-320` (inside `compile_symbolic`):  
```python
except Exception as exc:  # pragma: no cover
    ...
    return _compile_one_side(gm, example_inputs, is_backward=is_backward)
```  
`_compile_one_side` (line ~250) does `if any(_has_symint_shape(...)): return compile_symbolic(...)`.  
The fallback path re-enters the SymInt branch → stack overflow on the first dynamic-shape compile.  
(The “wave-3 minimal” symbolic path is therefore unusable.)

**HIGH 3: Double-backward registration never actually registers (timing + registry dependency)**  
`aot_autograd_glue.py:280-290` (inside `_compile_one_side` for `not is_backward`):  
```python
bwd_op = _REGISTRY.get(bwd_qualname)
if bwd_op is None:  # pragma: no cover
    return
...
register_double_backward(...)
```  
This runs **during** `tilelang_fw_compiler` (fwd GM). The corresponding bwd GM has not been lowered yet, so `bwd_qualname` is absent from `custom_op_wrapper._REGISTRY`. Registration is a no-op.  
`torch.func.grad(torch.func.grad(f))` therefore falls back to the default (incorrect) autograd path or errors.  
(This also violates the joint-design contract — the bwd op should be available before we wire the fwd.)

**HIGH 4: `register_double_backward` backward closure is fundamentally broken for realistic fused ops**  
`aot_autograd_glue.py:240-260` (`def backward(ctx, grad)` and surrounding):  
- Signature `backward(ctx, grad)` does **not** match PyTorch’s calling convention `backward(ctx, *grad_outputs)` for ops with >1 output. Multi-output fusions (extremely common) raise `TypeError: takes 2 positional arguments but 3 were given`.  
- `tangents = grad if isinstance... else [grad]` cannot handle the real `*grad_outputs` case.  
- `setup_context` does `ctx.save_for_backward(*inputs[0])` (the boxed-list hack) and sets `ctx._tilelang_has_atomic` which is **never read** (the closure captures `has_atomic_accumulator` instead).  
- The “trivial atomic” heuristic `if len(saved) == 1:` is unrealistic (aot saves *all* inputs to the custom_op; fused graphs almost always have >1). Most real atomic cases will now raise `DoubleBackwardUnsupportedError` or return wrong zero-grads.  
- Direct private access to `custom_op_wrapper._REGISTRY` + closed-over bwd_op creates tight, order-dependent coupling.

**HIGH 5: has_atomic_accumulator detection is brittle and misplaced**  
`aot_autograd_glue.py:305-310`:  
```python
has_atomic = any(
    ... "scatter_add" in str(node.target) or "index_add" in str(node.target) ...
    for node in getattr(gm, "graph", []).nodes
)
```  
String-matching on `node.target` (only on the *fwd* GM) is fragile, incomplete, and duplicates logic that should live in `FXToTileLang`. The flag is only used for the (already-broken) double-bwd path.

**Design/architecture issues (still present, non-blocking but should be cleaned)**

- **Leaky modules / violated boundaries** (`aot_autograd_glue.py:226`, `register_double_backward:200`, `__init__.py:40`): `_validate_graph` lives in the public `__init__` but is imported privately; autotune globals + `specialize_prim_func` live in the autograd glue file; glue reaches into `custom_op_wrapper._REGISTRY`.  
- **Awkward coupling** around the boxed `args: Sequence` convention (`custom_op_wrapper.py:140-170` `_impl` + `_runner` + setup_context hack). It works but ties the entire autograd wiring to a non-standard custom_op signature.  
- **Minor duplication** of `_check_no_grad` (called in both `_impl` *and* `_runner`).  
- **Over-engineering** in wave-3 pieces that are not yet wired (autotune shortlist is populated but never used by the lowering path; symbolic tile names are stuffed into `gm.meta` but the walker may ignore them). These could be removed for simplicity.

**Verdict**  
The package is **not ship-ready**. The aot_autograd path (the whole point of wave-3) has multiple hard blockers (import error, recursion, registration timing, backward signature). The legacy fallback still works, and the core custom-op + contiguity machinery is solid, but the joint autograd integration regressed in several places during the wave-3 changes.

Fix the five HIGH items above (move `_validate_graph`, fix the symbolic fallback guard, make bwd registration happen *after* bwd compile or via a post-pass, fix the backward signature + saved-tensor handling, and relocate the atomic flag into the artifact), then we can mark it green. Happy to iterate on concrete patches.
