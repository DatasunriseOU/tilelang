**Remaining HIGH-severity issues (functional correctness — must fix before green):**  
1. **Infinite recursion on symbolic-shape fallback** (`aot_autograd_glue.py: ~215-230` in `compile_symbolic` except block + `~290` in `_compile_one_side`):  
   ```python
   if any(_has_symint_shape(...) for ex in example_inputs):
       return compile_symbolic(...)   # <-- symint path
   ```
   Inside `compile_symbolic` except: `return _compile_one_side(...)` → re-evaluates the same `if` → stack overflow.  
   Concrete impact: any SymInt-bearing graph where the wave-3 symbolic walker fails (explicitly "best-effort" per comments) crashes the compile. This is the exact case the fallback was meant to handle. (Introduced or worsened in wave-3 symbolic path.)

2. **Double-backward registration never happens** (`aot_autograd_glue.py: ~300-320` in `_compile_one_side` fwd path + `register_double_backward: ~170-190`):  
   - Fwd compile calls `register_double_backward(fwd_qualname, bwd_qualname, ...)` *before* the bwd graph is ever lowered.  
   - `bwd_op = _REGISTRY.get(bwd_qualname)` is always `None` → early return, no `register_autograd` installed.  
   - Even if timing were fixed, `artifact.name` (fwd graph hash) ≠ bwd graph hash → qualname mismatch anyway.  
   Concrete impact: `torch.func.grad(torch.func.grad(f))` (or double-backward) silently falls back to eager or produces wrong gradients/NaNs. Wave-3 double-bwd claim is broken.

3. **_AUTOTUNE_CACHE write race (minor but visible in wave-3 addition)** (`aot_autograd_glue.py: ~70-90` in `autotune_select`):  
   Check-then-write with no lock (unlike `_REGISTRY_LOCK`). Multithreaded compile can bench the same key twice or lose the "fastest" result. Not security, but high-visibility perf regression for the new autotune shortlist.

Everything else (contiguity warnings, fake meta, boxed func import dance, `_validate_graph` fallback path) is solid and matches the wave-3 spec.
