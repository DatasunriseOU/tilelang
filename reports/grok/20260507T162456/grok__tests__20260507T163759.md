### 3. New 4th-category boundary-assumption bugs?
None that rise to security level, but two subtle boundary assumptions that are now live and untested:
- cc3194ae line 312 (CumSum2D kernel, reverse path): assumes `SEG >= 1` when applying identity-mask for `N < SEG`. If caller passes `SEG=0` (legal empty-segment edge from relay shape inference), the mask write becomes out-of-bounds on CUDA/HIP. Concrete attacker scenario: malicious Relax graph with `cumsum(..., axis=1, seg=0)` on GPU → silent memory corruption (no Python exception).
- 284a907e line 89 (`_detect_storage_overlap` outer-loop short-circuit): assumes buffers are never self-overlapping (`buf[i] == buf[j]` for i==j is impossible). If a graph contains an aliasing buffer passed twice, the early `continue` skips the self-check. Not a DoS, but can silently accept an overlapping schedule that wave-11 would have rejected.
