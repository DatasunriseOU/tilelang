**Remaining HIGH-severity issues (tests only – 2 total)**

1. **Brittle assertion locking in potentially incorrect behaviour**  
   `test_ptr_analysis.py:43-52` (`test_ptr_analysis_rewrites_addptr`)  
   ```python
   assert "tts.make_tptr" in rewritten
   ```
   This is the *only* semantic check on the rewrite output for the canonical fixture (`ADDPTR_MLIR`). It will pass even if the rewrite produces malformed `tts.make_tptr` ops, extra junk, or if the string appears for unrelated reasons in a future upstream change. Wave-1/2 left this untouched; it is now the weakest link in the smoke test.

2. **Major functional path under-tested (core purpose of the whole package)**  
   `test_ptr_analysis.py:58-63` (`test_ptr_analysis_extract_states_returns_list`) + complete lack of coverage for `ptr_analysis.py:280-300` (`_parse_states_json`).  
   The test only does `isinstance` checks. It never asserts:
   - `len(states) > 0` (or the exact count expected from the two `tt.addptr` ops in the fixture),
   - any `PtrState` field values (`offsets`, `sizes`, `strides`, `source`),
   - the “op” fallback path that is currently exercised by the real shim (`shim.cc:170-220` only emits `[{"op": "<printed MakeTensorPtrOp>"}]`).  
   This leaves the entire states-extraction contract (the reason `PtrAnalysis` exists) essentially unverified beyond “returns a list”.

def test_parse_states_json_handles_current_and_future_schema() -> None:
    # current shim output
    raw_current = '[{"op":"tts.make_tptr ..."}]'
    states = _parse_states_json(raw_current)
