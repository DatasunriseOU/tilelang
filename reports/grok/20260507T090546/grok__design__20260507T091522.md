### 3. Design & Architecture Assessment (high-level, as requested)
- **Abstractions respected**: `LowerTMAToPtrArith` is a pure `StmtExprMutator` that only touches `Evaluate(tma_load/tma_store)` nodes. It produces *exactly* the IR shape that `LowerPTXAsyncCopy` / `InjectSoftwarePipeline` already know how to consume. No violation of TIR buffer / Let / For idioms.
- **No leaky modules**: Descriptor decoding lives only in this file (inverse of `src/op/utils.cc` is isolated and guarded). Swizzle hint is preserved via a *single* well-documented pragma path.
- **No duplicated logic**: Offset math, dtype recovery, and target dispatch are all in one place. The Buffer-path intentionally re-uses the existing synthetic-buffer + Let pattern rather than inventing a new one.
- **Coupling is minimal and intentional**: The two string pragmas are the *only* bridge to `inject_pipeline.cc`. They are stripped/forwarded in a dedicated lowerer — no broad changes to pipeline core.
- **Extension points present**:
  - `TargetNeedsRewrite` / `TargetIsHopper` etc. → easy to add new “native TMA” targets.
  - `kEmitOpaque` toggle (even if we remove it later).
  - `BuildPointerArithCopy` is cleanly factored and could accept a custom body emitter if we ever want vectorized copies.
  - im2col is explicitly left in place with a loud warning + TODO — correct policy.
- **Naming & clarity**: Excellent. `DecodedDesc`, `BuildPointerArithCopy`, `pragma_tma_swizzle` are self-documenting. Comments cite exact lines in `copy.cc` and the Triton PR.
- **Over/under-engineering**: Perfectly balanced. No manual vectorization or unrolling here — defers to later passes (`LegalizeVectorizedLoop`, HIP vectorizer, Metal fragment-to-simdgroup). The serial For nest + synthetic buffers is the simplest thing that works and reuses the whole downstream stack.

### 4. Performance notes (design-driven)
The fallback is exactly as documented in the file header: pointer-arith loop → later vectorize / cp.async re-detection on Ampere → full native TMA only on Hopper+. No over-engineering in the pass itself. The `pragma_async_scope` tag ensures the pipeliner still sees the stage correctly even though the original TMA call is gone.
