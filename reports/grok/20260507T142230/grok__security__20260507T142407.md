### Concrete Security Findings (file:line, attacker scenario)

**Fixed / hardened (no longer exploitable):**
- **dsa_splitk_indexer_loss.py:480-520** (`topk_indices` path, wave-9#4 + wave-10): Always-on OOB check `((topk_idx64 < 0) | (topk_idx64 >= Sk)).any().item()` + explicit dtype/shape/device/contiguity validation **before** `scatter_` and kernel launch. Attacker controlling `topk_indices` (e.g., via adversarial ONNX export or poisoned graph) can no longer trigger GPU OOB read/write or silent adjacent-memory corruption via `scatter_`. Raises clear `ValueError` with min/max instead. Excellent.
- **dsa_splitk_indexer_loss.py:420** (zero-size guard): As above. Prevents UB/crash from zero-dim tensors.
- **lower_tma_to_ptr_arith.cc:280-300** (`tma_load_im2col`): Correct fail-closed (`LOG(WARNING)` + leave call in place). Non-NV backends reject cleanly; no incorrect pointer-arith fallback that would corrupt conv2d gather semantics.
- **lower_tma_to_ptr_arith.cc:200-250** (`DecodeTmaDescriptor` + `dtype_recovered`): Refuses lowering on unknown `CUtensorMapDataType` or malformed descriptor (`!ok`, zero/negative box). Prevents wrong `.bytes()` → byte-offset miscalculation → OOB / misalignment on Metal/HIP/CPU fallback paths. No silent memory corruption.
- **fp8_amax.py:780** (`fp8_pack_tilelang`): `if not math.isfinite(amax_val): raise FloatingPointError`. Prevents degenerate `inv_scale=NaN/0` from poisoning the entire FP8 tensor (weights/activations corruption downstream).
- **custom_op_wrapper.py:140-200** (`_ensure_contiguous_inputs`): Detects view-aliased inputs (`t._base is not None`) + forces `.contiguous().clone()` when needed. Prevents fused-kernel pointer writes from corrupting unrelated parent tensor storage (classic aliasing-style corruption / potential UAF). Warns once-per-(op,slot,reason) under lock.

**Remaining / new (actionable):**
- **reduce_op.py:140-180** + **reduce.h:80-100** (`reduce_prod` + `MulOp` + `AllReduce`): Wave-10 documentation-only fix. The contract ("caller MUST identity-pad inactive warp lanes to 1.0") is now clearly stated, but the actual lowering (`src/op/reduce.cc`) still does **not** enforce it (wave-11). On shapes where `dim` length is not a multiple of warp/wave width, inactive lanes pull garbage (MulOp identity=1.0, not 0). **Concrete risk today**: silent wrong product → corrupted loss/gradients (numerical integrity issue, not memory safety). Not yet a full "NaN attack" vector (garbage is usually small/zero), but an attacker who can influence reduce shapes/dims could force deterministic model divergence. Xfail test exists; wave-11 enforcement required before ship.
- **dsa_splitk_indexer_loss.py:430** (topk shape check): Only validates `.dim()==3` and `shape[:2]==(AB,ASq)`. **No check on `shape[2]` (TOPK)**. When `sparse_loss=True` and `TOPK==0`, `scatter_` does nothing → `index_mask` remains all `-inf` (no `0.0` positions set) → index-softmax produces NaN → KL loss NaN. The debug path (`_dsa_debug_enabled`) patches it; production does not. **Attacker scenario** (low likelihood but real): supply `topk_indices` with `K=0` (valid per current validation) → silent NaN loss (training crash / divergence). Add `if sparse_loss and topk_indices.shape[2] == 0: raise` (or handle gracefully) for completeness.
- **dsa_splitk_indexer_loss.py:570** (`sparse_loss=False`): `index_mask = torch.empty((AB, ASq, Sk), ...)` (uninitialized). Comment claims constexpr elimination so the kernel never reads it. Correct today, but a future kernel bug (or `SPARSE` guard failure) would leak uninitialized GPU memory into the computation. Minor integrity risk only (no active vuln).

**No other security issues found.** Threading primitives (`_FP8_AMAX_LOCK`, `_SCATTER_SCRATCH_LOCK`, `_REGISTRY_LOCK`, `_CONTIGUITY_LOCK`) are correctly used. Caches are bounded (`lru_cache(256)`, `_SCATTER_SCRATCH_LRU_MAX=8`). No tainted-data flows reach dangerous sinks. No user-controlled strings reach `os.environ`, `LOG`, or Torch ops in unsafe ways.
