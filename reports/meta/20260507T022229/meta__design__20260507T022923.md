## Finding 3
- **Severity**: high
- **File**: `src/transform/vendored/z3_prover.cc:292-335`
- **Issue**: `Bind(const Var&, const Range&, ...)` in BV mode clamps out-of-range binds to `[lo, hi+1)` and logs once. This is unsound for proofs: if caller binds `Var x in [0, 2^40)`, clamping to `[INT32_MIN, INT32_MAX]` makes `CanProve(x >= 0)` succeed, but original code may have `x = 1<<39` which is negative after clamping. If a pass uses `CanProve` to elide a bounds check, it will incorrectly remove the check for values outside BV range. Silently changing the range breaks the proof contract. For memoization: always `memo_.emplace(var, var_expr)` before any early return, else later lookups recreate a free var.
