## Finding 1
- **Severity**: low
- **File**: `tilelang/transform/metal_fragment_to_simdgroup.py:112`
- **Issue**: `os.environ.get("TL_LOG_SIMDGROUP")` controls verbose logging that prints buffer names, shapes, dtypes, and Z3 queries. An attacker who can set environment variables or trigger logging in a shared build/test environment can leak information about tensor layouts, model structure, and memory addressing details. This is an info leak, not direct RCE, but still security-relevant when TileLang runs in multi-tenant CI or compiler-as-a-service.
- **Fix**: Gate verbose logs behind a compile-time flag, not env var, or redact symbolic expressions before logging. Example:
  ```diff
  - if os.environ.get("TL_LOG_SIMDGROUP"):
  + if logger.isEnabledFor(logging.DEBUG):
       logger.debug("simdgroup-detect: buf=%s dtype=%s", buf.name, buf.dtype)
  ```
  And never log full symbolic `shape` or `addr_value` from user IR.

## Finding 3
- **Severity**: medium
- **File**: `tilelang/transform/metal_simd_lift.py:245`
- **Issue**: `_butterfly_stages` asserts `1 <= shift < 32` to prevent out-of-range shuffle masks. However, `extent_val` is only checked for `2 <= extent_val <= 32` and power-of-2 in `_visit_for:348`. If an upstream pass or future change bypasses that check, or if `math.ceil(math.log2(extent))` produces `n_stages=6` due to float rounding on `extent=33`, `top = 1 << 5 = 32` and the first shift would be 32, violating `shift < 32`. The assert would fire, causing a compiler DoS. This is a logic bug that can be triggered by malformed IR, not external input, but compiler passes should be hardened against corrupted IR to avoid crash-then-restart loops in build services.
- **Fix**: Clamp shift and validate before assert:
  ```python
  for shift in out:
      if not (1 <= shift <= 16):  # simd_shuffle_xor mask must be < lane count
          raise ValueError(f"Invalid shuffle mask {shift} for extent={extent}")
  ```
  Also ensure `extent_val <= 32` is checked immediately after parsing, not only in the later conditional.

## Finding 4
- **Severity**: info
- **File**: `tilelang/transform/metal_fragment_to_simdgroup.py:95`
- **Issue**: `_z3_simdgroup_eligible` accepts `addr_value: int | None`. Comment says “When None, the address constraint is *omitted*”. If a future version passes a TIR expression or symbolic address here, `int(addr_value)` will raise `TypeError`. No sanitization. Currently only called with `None`, but the function signature allows misuse. In a compiler, an uncaught exception aborts the pass and can be used for DoS if an attacker controls IR that reaches this path.
- **Fix**: Type-check and reject non-None non-int:
  ```python
  if addr_value is not None and not isinstance(addr_value, int):
      return False, "addr_value must be concrete int"
  ```
