## Finding 3
- **Severity**: medium
- **File**: `src/transform/loop_vectorize.cc:1030-1044`
- **Issue**: `AlignmentMemoKeyHash` uses `std::vector<size_t>` as part of the tuple key. Hashing walks every index expr's structural hash on each probe, then copies the vector into the key. ## Finding 1
- **Severity**: high
- **File**: `src/transform/vendored/z3_prover.cc:372`
- **Issue**: `Bind(const Var& var, const Range& range, ...)` commits a `memo_` entry for `var` before checking whether the range fits in the active BV width. When `bv_width_ > 0` and the caller's range exceeds BV bounds, the code first hits the warning block at L382-399, then clamps and adds constraints L412-414, but it never returns early for the clamp case. It falls through to L415-421 where it unconditionally calls `memo_.emplace(var, var_expr)` again and adds `MakeIntVal(min_value) <= var_expr` with the *original* out-of-range `min_value`. This results in two problems: 1) duplicate memo insertions, 2) solver gets both clamped and unclamped range constraints, making the state inconsistent and potentially UNSAT. The `commit_memo = false` flag is set but never checked.
- **Fix**: Restructure the BV-range handling to be mutually exclusive with the normal path. Example:
```cpp
if (bv_width_ > 0 && bv_width_ < 64) {
  int64_t lo = (bv_width_ == 32) ? INT32_MIN : -(int64_t{1} << (bv_width_ - 1));
  int64_t hi = (bv_width_ == 32) ? INT32_MAX : ((int64_t{1} << (bv_width_ - 1)) - 1);
  if (min_value < lo || max_value > hi) {
    if (!bv_range_warned_) { /* warn */ bv_range_warned_ = true; }
    int64_t clamped_min = std::max<int64_t>(min_value, lo);
    int64_t clamped_max = std::min<int64_t>(max_value, hi + 1);
    if (clamped_min >= clamped_max) { clamped_min = lo; clamped_max = hi + 1; }
    memo_.emplace(var, var_expr);
    solver.add(MakeIntVal(clamped_min) <= var_expr);
    solver.add(var_expr < MakeIntVal(clamped_max));
    return; // prevent fallthrough
  }
}
memo_.emplace(var, var_expr);
solver.add(MakeIntVal(min_value) <= var_expr);
solver.add(var_expr < MakeIntVal(max_value));
```

## Finding 3
- **Severity**: medium
- **File**: `src/transform/vendored/z3_prover.cc:82`
- **Issue**: Silent semantics change via warnings. `MakeIntVal` and `Bind` on out-of-range constants emit `LOG(WARNING)` once, then clamp/wrap and continue. For a proof system, silent wrap of `IntImm(3000000000)` to `-1294967296` in BV32 mode can make unsound proofs appear sound.
