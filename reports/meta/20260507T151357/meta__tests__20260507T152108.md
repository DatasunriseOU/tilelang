**3.3 `reduce.cc:183-187` MulOp identity leaks via dtype promotion**

But if `dst` is `int8`, `make_const(int8, 1)` then cast to fp32 accumulator gives 1.0f32. However, if `dst` is `uint8`, identity should be 1, but if user does product of values >1, overflow wraps. Not a bug, but test missing.
