### 2. HIGH grok/chatgpt missed: Race condition in op registry under autograd save

**custom_op_wrapper.py:38** `_REGISTRY_LOCK = threading.Lock()`  
**custom_op_wrapper.py:45** `_CONTIGUITY_LOCK = threading.Lock()`  
**custom_op_wrapper.py:87** `key = (op_qualname, i, reason)` used in registry

**Bug**: The two locks are never acquired together. `register_autograd` and cache lookups can race. Two threads compiling the same op can both miss the cache, both build `_impl`, and one will overwrite the other’s `artifact` binding. 

**Concrete attacker scenario**: TorchDynamo compilation is often triggered by concurrent inference requests in a web server. If your service compiles on first request, attacker sends 2 parallel requests for `POST /embed` with a new model. Thread A writes `artifact_v1` to registry, Thread B writes `artifact_v2`. If A’s `_impl` closure captured `artifact_v1` but the registry now points to `artifact_v2`, you get kernel version skew. For ops that do authz, like `aten.masked_select` used to filter rows by user_id, you can end up executing an old kernel with stale mask logic against new data. **Fix**: Wrap the entire cache check + populate in one critical section. Line 238-245 should be inside `_REGISTRY_LOCK`.

### 3. HIGH grok/chatgpt missed: Integer overflow in block size math → OOB write in generated TIR

**fp8_amax.py:149-154** `_pick_block_size`  
**fp8_amax.py:167-170** `_bucket_n` returns `1 << (n - 1).bit_length()`  
**fp8_amax.py:311-319** Enforces `block_size % threads == 0` but not overflow  
**dsa_splitk_indexer_loss.py:340-343** Only checks `> 0`, no upper bound  
**dsa_splitk_indexer_loss.py:2049-2052** `block_K = 32 if k >= 32 else k` — user-controlled `k`

**Bug**: All `BLOCK_*` constants come from FX graph shapes. If a user can submit a tensor with `dim=1<<30`, then `T.ceildiv(n, block_N)` in **fx_to_tilelang.py:1715** becomes `1<<30 / 64 = 16777216` blocks. Grid launch overflows `int32`. On CUDA, gridDim.x is 32-bit. On Metal, threadgroup count is 32-bit. You get wraparound to a small grid, but kernel code assumes full coverage. The tail loop at **reduce_op.py:189-199** will accumulate the same value `threads` times because warps think they own elements they don’t.

**Concrete attacker scenario**: You expose a model-as-a-service endpoint that compiles user-provided shapes. Attacker sends `torch.randn(1, 1<<30, 16)` to trigger `BLOCK_M=128` path. `T.ceildiv(1<<30, 128) = 8388608` which fits int32, but `BLOCK_K=32` and `k=1<<30` gives `num_stages=2` pipeline with 33554432 iterations. TileLang unrolls this. Generated Metal will OOM at compile time, but on CUDA it compiles and launches 8M blocks. If your kernel writes to `C[by * block_M, bx * block_N]`, wrapped `bx` makes two blocks write same address. For `T.atomic_max` in **fp8_amax.py:371-373**, you lose atomicity guarantees across wrapped blocks → amax is wrong. If amax guards fp8 overflow, you get silent NaN propagation, which is a model integrity issue.

**Fix**: 
1. **fx_to_tilelang.py:1715** Add: `if T.ceildiv(n, block_N) > 1<<31: raise ValueError("Grid overflow")`
2. **dsa_splitk_indexer_loss.py:340** Add upper bound: `if any(x > 1<<20 for x in [BLOCK_SQ, BLOCK_SK, BLOCK_D]): raise ValueError`

### 6. NEW HIGH only Meta would catch: Silent correctness bug in warp reduction → auth bypass

**reduce_op.py:189-199** Comment: “during warp reduction, the same value would be accumulated multiple times”  
**reduce_op.py:508-510** `tl.warp_reduce_sum` — all threads get same value  
**dsa_splitk_indexer_loss.py:444-448** “once so accumulator-init paths execute deterministically”

**Bug**: The TIR you emit uses `T.reduce_max` which maps to `tvm_thread_allreduce`. On Metal, that’s implemented as shared-mem + barrier. If `BLOCK_SIZE % 32 != 0`, the last warp is partial. The comment in **reduce_op.py:199** admits the value is accumulated multiple times for inactive threads. If you use this to compute `softmax` denominators in **fx_to_tilelang.py:320-321**, you get `d_h` wrong by a factor of `32 / active_threads`. 

**Concrete attacker scenario**: You fuse a model that does `logits = q @ k.T; mask = logits < threshold; out = masked_fill(logits, mask, -inf); probs = softmax(out)`. If `warp_reduce_max` returns 2x the real max due to double-counting, your `threshold` comparison fails. An attacker can craft `q,k` such that a disallowed token’s logit is 0.51*max, but buggy max is 2*real_max, so `0.51*max < 0.5*2*max` → token is masked when it shouldn’t be, or vice versa. This is a policy bypass in LLM safety filters that use compiler-fused kernels.

**Fix**: **reduce_op.py:508** Add predicate: `if threadIdx.x < active_threads` before contributing to reduction, or mask lanes. For TileLang, use `T.reduce_max(val, where=lane_active)` if available.
