### 1. `_q_cache_bytes` int overflow guard + `None` propagation `e946f98`
**What to check**: `fp8_amax.py`, `dsa_splitk_indexer_loss.py` likely

**Security risk: Integer overflow → OOB write/heap spray**
If `_q_cache_bytes` is computed from user-controlled tensor shapes, an overflow before the guard lets an attacker allocate a tiny buffer but write gigabytes.

2. `None` propagation: If `_can_use_q_cache_v5` returns `None` and caller does `cache[None]`, you get `TypeError`. But if caller does `if cache:` then proceeds, `None` becomes exploitable. Ensure every `_tiled` call site checks `is not None`.

### 2. `reduce_prod` ICHECK→LOG(FATAL) "ValueError:" `dde5e28c`
**Files**: `reduce.cc`, `reduce.h`, `reduce_781b94.h`

**Security risk: Error-handling downgrade = DoS + info leak**
`ICHECK` is compile-time/off in release. `LOG(FATAL)` aborts. If you changed to throw `tvm.error.InternalError` to make it "catchable", now attacker can trigger it via malformed model IR and catch the exception in Python.
```python

    run() # hits LOG(FATAL) -> now InternalError

```
**Verify**:

2. If this path is in graph-compiler, remote model upload = remote DoS. Every request kills worker. Check if there’s a `try/catch` at RPC boundary. If not, 1 bad model = cluster crash.

**Runtime vs static_assert**: Runtime check is correct because tensor shapes are dynamic. Static_assert would miss attacker-controlled dynamic shapes. But you must ensure the check is *before* any `alloca`/`VLA` sized by the product.

### 4. `_detect_storage_overlap` short-circuit O(n²)→O(n) `284a907e`
**Files**: `dsa_splitk_indexer_loss.py`, `custom_op_wrapper.py`

**Security risk: TOCTOU race in alias analysis**
If this function is used to decide whether two tensors can alias for in-place ops, the short-circuit means you return `no_overlap` faster. Attacker with two threads: T1 passes tensors A,B through `torch.compile`. T2 mutates `A.storage()._data_ptr()` between `_detect_storage_overlap` check and kernel launch.
```python

    return a.add_(b)

# T2: while f is JITing, do b.set_(a) # now they overlap
# Kernel runs: in-place add with aliasing -> writes past end, corrupts python heap
```
**Verify**: `dsa_splitk_indexer_loss.py:line?` - Is there a `with torch.no_grad():` or GIL release between check and use? If yes, race exists. Short-circuit didn’t introduce it, but made the window smaller. If this is used for security boundary like "user A can’t read user B’s tensor", race = authz bypass.

**Lock-DoS note**: You said documented as "practical-small". If `_detect_storage_overlap` takes a global lock, all-overlap case was O(n²). Now O(n) but still `0.04ms * n`. With `n=1M` tensors from attacker model, 40s hold. If this is in RPC handler, 1 request = worker stall. Check for lock granularity.
